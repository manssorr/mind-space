## UI/UX review gates (set 2026-07-12)

Every UI-touching task, in addition to the rules above:
- **Before implementing**: review the interaction surface being touched AND its
  neighbors - hover states (CSS :hover, group-hover, React-driven), focus and
  keyboard paths, overlays/portals/z-index, pointer-event propagation (React
  tree vs DOM tree differ for portals), cursor feedback. Write the risks into
  the task before code is written.
- **After implementing**: a dedicated UX pass in the live browser beyond the
  functional checklist - hover every interactive element in and around the
  change, confirm nothing leaks through open overlays (hover effects behind
  menus/popovers), keyboard traversal, both themes. Functional-only
  verification is not acceptance.
- Verification tooling note: CSS :hover does NOT respond to dispatched
  synthetic events - hover checks need real input (CDP hover / Playwright),
  and `document.querySelectorAll(":hover")` reads the live hover chain.

Origin: the Base UI context menu shipped with hover effects leaking to
widgets behind the open menu (aria-hidden was applied outside but
pointer-events stayed auto). Functional verification passed; nobody hovered
around. Three portal/event-model bugs in one feature = this gate.

## Runtime verification (2026-07-11, live dev server + CDP-driven Chrome)

Findings were re-verified against the running app, not just code reading:

- **CONFIRMED - stopwatch wipes undo + storage blowup** (plans 003/004): 3 s of a running stopwatch took `undoStack` from 1 to 50 entries (cap) and the persisted blob from 3.7 KB to 105 KB. Adjacent snapshots differ only in the stopwatch's `elapsed`/`laps`, proving all history entries are tick garbage. `redoStack` cleared.
- **CONFIRMED - quick-link crash, persisted** (plan 002): saving `http://` via the real edit input killed the whole app (0 widgets rendered, Next 16 default "This page couldn't load" boundary) and the crash survives reload because the value is persisted. Recovery required `localStorage.clear()`. Note: `foo bar` does NOT throw in current Chrome (URL parser percent-encodes spaces); throwing inputs include `http://`, `https://`, `https://%` - and blur saves, so a half-typed URL is enough.
- **CONFIRMED - invalid month-boundary date keys** (plan 005): January 2026 habit grid renders filler cells keyed `2026-00-29`, `2026-00-30`, `2026-00-31` (month "00", wrong year; should be `2025-12-*`). Habit filler cells do not toggle completions, so habit damage is display/streak lookups; the calendar widget shares the same grid function and saves notes under these keys.
- **REFUTED - space-pan double speed**: see rejected list below.
- **UNVERIFIED - timer freeze in background tabs** (plan 004): the automation browser never fires `visibilitychange` on tab switch (visibility stayed `visible`; timers ran unthrottled), so browser throttling could not be reproduced in this harness. The mechanism (tick-decrement + documented Chrome interval clamping in hidden tabs) stands at MED confidence; verify manually by minimizing a real browser window for 2 minutes with a timer running. Plan 004's timestamp redesign is justified independently: it also makes remaining-time survive reload and tab close, which are design facts, not claims.
- Also observed: while the stopwatch runs, the 300 ms write debounce is reset by every 10 ms tick, so localStorage writes starve until the stopwatch stops or the tab hides - a data-loss window during any continuous-update widget. Covered by plan 004 (ticks stop hitting the store).

## Findings considered and rejected

(So nobody re-audits them.)

- **Clipboard non-null assertion in `pasteWidgets`** (`store/index.ts:671`): zustand `set` is synchronous; no interleaving can null the clipboard mid-callback. Style nit, not a bug.
- **Stopwatch loses elapsed time on unmount**: false; elapsed is persisted on every tick, and after plan 004, timestamps make it exact. Collapse-while-running pauses accumulation, which is defensible behavior.
- **postcss advisory GHSA-qx2v-qp2m-jg93 (moderate, transitive via next)**: build-time only; user widget data never flows through postcss. Monitor for a Next.js patch release; `npm audit fix --force` would downgrade next and must not be run.
- **lucide-react minor version lag**: routine caret-range noise, no action.
- **Space-pan double-speed pan**: REFUTED by runtime test (2026-07-11): synthetic space+drag of 100 px moved the canvas exactly 100 px; the duplicated handlers compute absolute offsets from their own snapshots and shadow each other. Plan 006 keeps the consolidation, drops the bug claim.
- **"Lockfile invalid / extraneous packages" and "AGENTS.md points to nonexistent `node_modules/next/dist/docs`"**: both were artifacts of `node_modules` not being installed in the audit worktree. Run `npm install` before believing either.
- **God-store split (748-line `store/index.ts`)**: premature at this size; plans 003/004 already extract the highest-risk seams (persistence, history). Revisit if the file passes ~1200 lines or collaboration features land.
- **Module-scope `beforeunload`/`visibilitychange` listeners never removed**: dev-HMR annoyance only; noted in plan 003 maintenance notes.
- **Prettier / editorconfig / CI workflow**: solo project, ESLint + verify script suffice for now; CI deferred until a second contributor.
- **Favicon fetch sends bookmarked hostnames to Google** (`quick-link-widget.tsx:16`): real privacy inconsistency with the README's "everything local" framing, but low severity; recorded in plan 002's maintenance notes as a candidate settings toggle.
- **Duplicated debounced-save pattern across ~6 widgets**: real duplication, low leverage; the shared-hook extraction can ride along with the first bug it actually causes.
- **README says the note widget is "rich text"**: it is a plain textarea. Either fix the README word or treat rich text as a roadmap item; too small for a plan.
